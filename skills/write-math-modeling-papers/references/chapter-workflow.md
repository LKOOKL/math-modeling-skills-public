# 通用章节写作流程

## 结构路由：先分配功能，再确定层级

一级骨架采用 [用户国赛模板契约](user-template-contract.md#固定大框架)：摘要 → 问题重述 → 问题分析 → 模型假设 → 符号说明 → 数据预处理 → 逐问模型建立与求解 → 模型的评价与推广 → AI 声明／参考文献／附录。摘要位于文首、正文定稿后写；每问以独立 `\section` 覆盖“任务承接—模型与求解材料—过程展示—结果回答—可信性与边界”，结果分析及各类检验分别设为本问的 `\subsection`。下列经验路由用于模板内组织，不自行替换一级骨架。

| 结构路由 | 适用条件 | 编辑安排 |
|---|---|---|
| 逐问闭环（默认） | 各问对象、模型或输出有明显区别 | 每问就近说明方法、结果和证据；首次完整答案留在本问 |
| 共享基础材料＋逐问扩展 | 用户提供的数据处理、变量、机理或基础模型被至少两问复用 | 共用数据置于数据预处理，数学关系在首次使用的问题中说明；后问引用并交代新增内容，普通写作不另建共享总章 |
| 总章分问（仅显式格式例外） | 用户另有明确层级要求或适用的强制模板要求 | 记录要求来源；各问与其分析小节保持父子归属，其余情况采用每问 `\section`、分析 `\subsection` |
| 依赖链／语义任务序列 | 用户方案已存在前问输出作为后问输入的明确关系 | 保留模板题号顺序，以首段与交叉引用说明实际依赖、传递量、单位和用途 |
| 独立结论（显式例外） | 用户明确要求或适用强制模板要求 | 记录依据，只汇总已有答案；通常在各问结尾及模型评价与推广中收束 |

### 逐问结果分析的层级与归属

- 每问 `\section` 下分别设置“结果分析”“误差分析”“敏感性分析”三个 `\subsection`；其他适用的稳定性、稳健性、可行性、模型对比等分析也分别设置同级小节。标题可加入本问对象或指标；小节内可用段落或 `\subsubsection` 细分。
- 分析小节就近接在本问求解与结果之后，写明本问对象、已有检验设置、关键指标或结果、解释及适用边界。篇幅较少时保留简短小节，不用散落段落、统一检验总章或附录索引替代。
- 共用的指标定义、基准和检验方法可在共享基础处介绍一次；各问在相应小节引用该方法，并保留本问的结果、解释与边界。相同模型或轨迹复用同一证据时，说明复用依据和覆盖范围；不能仅写“见统一检验”。大型跨问表可集中存放，各问仍摘述有依据的本问关键结果。
- 缺少材料时，在本问对应小节写 `[待提供：本问所缺的具体检验材料]` 并同步登记缺口；确实不适用时，保留小节并说明基于题目和已有模型材料的理由。不得为填满小节虚构检验、把未执行写为通过，或在写作模式补算。
- 全局“模型评价”等收尾章节只综合已在各问呈现的结论；误差、敏感性等结果分析不另设统一总章集中承载。用户明确要求或强制模板规定其他层级时记录依据，并保留逐问对应分析。

```latex
\section{问题一的模型建立与求解：具体任务}
\subsection{模型建立}
\subsection{模型求解}
% 每个最终作答模型至少展示伪代码或流程图之一，置于本问
\subsection{结果分析}
\subsection{误差分析}
\subsection{敏感性分析}
% 稳健性、可行性等其他适用分析分别增设同级小节
\section{问题二的模型建立与求解：具体任务}
% 同样在本问下分别编排结果分析及各类检验
```

本文件负责章节组织与表达。技术细节均限于用户已提供的模型、推导、算法、参数、结果、图表和检验材料；缺失或矛盾项记录具体位置并向用户核问。符号、量纲、公式与结果的一致性疑点可报告，禁止为补齐章节而选模、构建模型、补推导、算数、调参、写改运行代码或设计执行实验。题型表达见 [problem-type-writing.md](problem-type-writing.md)，标题细则见 [heading-naming.md](heading-naming.md)。

## 固定写作顺序

1. **材料与证据映射**：列出题问、用户材料位置、直接答案、关键数值及单位、图表、检验与边界、拟放章节；标出缺失项和冲突。
2. **逐问主体**：先写每问的任务承接、模型表达、求解材料叙述与伪代码／流程图，再按本问 `\subsection` 分别写结果分析、误差分析、敏感性分析及其他适用检验。
3. **跨问共享与评价**：抽取确实复用的内容，明确接口，完成有前文证据的评价。
4. **前置章节**：依据已写主体压缩问题重述、问题分析、假设和符号说明。
5. **摘要后写**：正文定稿后提炼总任务、逐问方法、具体结果和可信性边界。
6. **LaTeX 终审**：按 [latex-production.md](latex-production.md) 执行纯排版编译，审阅用户提供或本次编译得到的 PDF，检查章节标题与引用、公式与符号、图表与说明、数值呈现、标签、PDF 书签及版面；记录尚未核验项。纯排版编译限于文稿生成，不运行技术计算代码或补做技术验证，不输出正文目录。

局部写作任务只执行相关步骤及其必要的前后文核对，无须扩展为整篇重写。写作顺序与最终章节顺序分开处理；内部章节提纲仅用于规划和审查，不输出正文目录。

以下“任务—方法—结果”等微结构列出按内容选择的信息功能，供组织材料和检查论证使用。允许省略不适用项、在相邻段落中合并或承接已说明的内容；无需把每个功能写成独立句子，也无需为填齐槽位重复信息。只有当前任务或主张确实依赖某项缺失材料时，才登记相应缺口。

### 规划输出 A：逐章写作卡

材料映射后，按当前任务范围填写写作卡，明确各章或节准备表达什么、依据在哪里、交付什么。局部任务只填相关章节；技术内容全部来自用户材料，信息顺序可按适用功能合并调整。

| 章节 | 目标 | 输入来源及状态 | 信息顺序 | 交付内容 |
|---|---|---|---|---|
| ［章／节名称及对应题问］ | ［本节需要回答或说明的事项］ | ［用户文件／页码／段落；状态：用户确认、附有证据、待提供、存在冲突］ | ［拟采用的适用信息功能及承接关系］ | ［拟完成的段落、直接答案、图表说明或索引］ |

### 规划输出 B：载体布置表

为当前任务涉及的公式、图、表、结果、引用和附件逐项安排位置；局部任务只填相关载体，不适用的类型可省略。状态反映材料与编排进度，不表示已执行技术验证；材料缺失时记录具体缺口，不创建技术内容。描述型载体的“支撑主张”可填写说明用途，“引导与解释”按类型和当前主张需要填写。

| 类型与编号或来源 | 支撑主张 | 拟放位置 | 引导与解释 | 状态 |
|---|---|---|---|---|
| 公式：［用户公式编号／来源］ | ［已有关系或约束］ | ［章／节／段落］ | ［必要定义与作用说明］ | ［材料／编排状态］ |
| 图：［已有图号／文件］ | ［支持的已有判断或说明用途］ | ［章／节／段落］ | ［按需引导及读图解释］ | ［材料／编排状态］ |
| 过程展示：［题号／模型／算法或流程图编号］ | ［已有模型的处理逻辑］ | ［本问模型建立或求解小节］ | ［输入输出、主要步骤、来源及正文解释］ | ［完成／具体缺口］ |
| 表：［已有表号／来源］ | ［支持的已有判断或说明用途］ | ［章／节／段落］ | ［字段、单位与必要解读］ | ［材料／编排状态］ |
| 结果：［用户结果编号／文件位置］ | ［对应题问的直接答案］ | ［首次完整答案位置］ | ［数值条件、题目含义及必要边界］ | ［材料／编排状态］ |
| 引用：［用户文献／来源标识］ | ［被支持的具体表述］ | ［相邻引用位置］ | ［来源归属及必要说明］ | ［材料／编排状态］ |
| 附件：［用户实际文件名／位置］ | ［支撑内容或材料用途］ | ［正文指引及附录索引］ | ［与题问及正文内容的对应说明］ | ［材料／编排状态］ |

## 摘要：正文定稿后的任务浓缩

先用一句话说明总任务。随后逐问从“任务—用户方法—关键结果—可信性／边界”中选择适用信息组织摘要，每问保留代表性结果及已有具体数值、单位和适用条件；相邻句可共享已经交代的条件。方法名称、技术细节和性质主张均应能定位到正文。

可用信息槽位：针对问题 N 的［任务］，采用用户已确认的［方法］，得到［关键结果及数值、单位］；依据［已有检验及结果］，该结论适用于［条件／边界］。槽位仅供组织已有信息，可按内容合并或省略不适用项；当前摘要主张所需的材料缺失时向用户索取。

- 关键词覆盖研究对象、主要方法和任务。
- 摘要中的数值逐项与正文及用户指定结果材料核对，避免只保留笼统的“效果良好”。
- 摘要不含公式、图表和正文未建立的新结论。
- 检验证据缺失时保留缺口与已知边界，不生成可信性结论。

## 问题重述：压缩题意并定位交付

从“对象—条件—输入—输出—任务清单”中选择适用信息组织重述，可在同一短段中合并。只保留理解任务必需的背景，明确适用的时间／空间范围、已知条件、输入资料和各问要求的答案形式；题号与原题一致。前问输出参与后问时，简要标明依赖关系。

禁止大段复制题面。重述中的任务转换只重新表达题目已要求的内容，不添加新的优化目标、评价指标或研究任务。

## 问题分析：解释已采用路线

每问从“难点—用户方案处理路线—章节／跨问接口”中选择适用信息展开，可跨相邻段落承接：

1. 从题面及用户材料指出本问确有的难点或信息差异。
2. 依据用户已经给出的理由解释现有预处理、模型和求解步骤如何处理难点。
3. 指明正文哪个单元展开相应内容，哪些已有输出传给后问。

方法选择理由尚未提供时，精确询问“该方法用于处理哪项困难，依据位于何处”；不比较候选方法、不规划新解法。用户材料只有方法名时，应暴露理由缺口，避免编写通用适配论证。

## 假设与符号：统一实际使用的前提和语言

### 假设

假设说明从“内容—依据—作用—边界”中选择适用信息，已有共同依据或边界可集中交代，并标明正文实际调用的公式、约束或解释位置。题目直接给定的条件与作者引入的假设分开；经验判断使用用户提供的数据或来源支持。假设表只保留正文实际调用者，未调用项列为编辑疑点请用户确认。

假设的作用描述限于用户材料中已经存在的简化或限制。假设不足以支持某公式时报告断点，不补设假设；假设失效造成的影响缺乏依据时只保留待确认问题。

### 符号

核心、跨章、高频符号集中成表，列出符号、含义、单位及必要的取值域或索引范围；局部符号在首次使用处就近定义。全文统一集合、上下标、时间／对象索引和单位，确保一个符号在同一语境中含义稳定。

检查公式、表头、图轴和正文称谓是否一致。发现同名异义、量纲疑点、未定义上下标或单位冲突时记录位置并询问，不自行更改技术含义或换算数值。

## 逐问主体：从任务承接到可定位答案

### 开头与结尾

开头交代本问要求的输出、已有输入、继承前问的内容及本问已有新增条件；独立问题无需制造依赖。主体围绕用户技术材料展开。首次完整答案放在本问结果节首段或紧邻核心表格处，结尾用短段回扣任务、可信性边界与下游接口，避免把首次答案推迟到摘要或全文结论。

### 模型表达与公式段

公式附近按内容选择“现实动机—变量定义—编号公式—逐项解释—本节作用”等信息功能；相邻段落可合并承接，已清楚定义或不适用的内容无需重复。可检查：

1. 说明用户公式所刻画的对象关系或任务要求。
2. 在公式前定义必要变量、参数、集合、索引和单位。
3. 按用户材料呈现公式并编号，保留限定条件。
4. 解释各项对应的现实意义、参数来源和条件，按已有推导交代相邻公式联系。
5. 说明此式在本节的目标、约束、关系表达或输出接口中的作用。

模型汇总应让读者找到用户给定的目标、关系、变量域和边界条件。长推导依照用户已有中间式分段并说明承接关系；遇到中间式缺失、符号跳变或疑似矛盾，标出缺口交由用户补充。任何一致性审阅均不转换为推导、特殊值计算、回代或复算。

### 求解材料叙述

从“选择依据—输入—核心步骤—输出”中选择适用信息描述用户已经完成的求解，允许跨相邻段落承接。根据现有材料按需交代初始化、参数来源、数据划分、停止条件、精度、解的选择规则和计算成本；只写与理解过程及结果有关的已知细节。

每问每个最终作答模型至少展示伪代码或流程图之一。可将已有算法说明、模型关系或已提供源码忠实转排为展示型伪代码／流程图及 LaTeX/TikZ 源码，按 [过程展示规则](user-template-contract.md#每问模型的过程展示) 核对来源和覆盖；不设计新算法、不补推缺失步骤、不改写或运行求解代码。改进方法已有材料时，按“原有局限—用户改动—已有比较证据—收益与代价”叙述；未提供比较结果时不声称性能提升。步骤、输入输出、参数或版本不明时登记具体缺口。

### 结果与图表

结果叙述从“直接答案—数值—图表证据—趋势／比较—题目含义—条件边界”中选择适用信息，可由相邻段落和图表共同承担。没有趋势或比较任务时无需补写对应内容；直接答案仍须可定位。精确值优先引用用户提供的表或结果材料，趋势优先引用用户已有图；当前答案或主张所需材料缺失时向用户索取，不从图片估算精确值。

分析型图表按需在前文说明观察目的与比较对象，在后文或相邻段落选择关键读数、可见规律、用户材料支持的原因及任务意义进行解释；不适用项可省略。符号表、输入说明表、方案清单等描述型表主要交代用途、字段含义、单位、条件和读取方式，无须附加趋势、原因或规律分析。只有当前主张确实依赖解释且用户材料缺失时，才登记解释缺口；单纯报告可见现象时不强求原因，也不将观察升级为因果结论。

- 数值保留单位、对象范围、时间条件、展示精度及已有区间。
- 表题、图题和图注说明对象、指标、条件及必要缩写。
- 结果表与说明就近排布；用于支持主张的图表明确对应结论，描述型表说明其用途。
- 每问首个完整答案可由短段加核心表格共同组成。
- 差值、比例、极值或排名只有在用户已提供时才引用，不为加强描述而新增计算。

### 检验与边界

在本问各自的误差、敏感性等 `\subsection` 内，从“对象—用户方法—指标—结果—判定—适用边界”中选择适用信息叙述已有检验；同类检验内部可跨相邻段落合并。涉及阈值或比较判定时写明用户提供的阈值及来源、数据范围、比较对象和支持的具体主张。敏感性材料按需交代已有扰动范围、保持不变的条件、输出指标及结论边界。

检验材料不足时明确询问缺少的指标、阈值、结果或支持关系，不设计检验、不补跑、不复算；已运行、已通过等状态只依据用户提供的记录表述。正文审阅发现的一致性疑点应单列为待确认项，不作为新的检验结果。

## 跨问评价与按需结论

评价优点时从“设计特征—前文证据—价值”中选择适用信息，评价局限时从“条件—影响—改进方向”中选择适用信息，可合并为连贯段落。优点必须指向已有公式、结果、图表或检验证据；局限说明受影响的对象与适用范围。改进方向仅整理用户已提出的方向，无相关任务或材料时可省略；当前评价主张确需相关材料时精确询问，不提出新技术路线。

推广应有用户提供的适用条件、比较或验证依据，明确哪些范围已获支持、哪些只是用户提出的设想。避免泛化的“普适性强”“精度高”“具有推广价值”。

通常在模板的“模型的评价与推广”中综合已有结论，分别说明优点、缺点和有依据的推广边界；独立结论章仅按明确要求增设。各问直接答案仍保留原位，综合段的数值和条件与原位一致。

## 段落、章节接口与末尾材料

论证段落可从“主张—证据—解释—作用”中选择适用信息：说明要表达的判断，引用已有公式、数值、图表或文献，并按需解释其支持关系与作用。信息可跨相邻段落合并，已清楚交代或不适用的功能可省略；定义、导航和描述段无需套用整条链。当前主张确需的证据或解释缺失时保留疑点。

章节开头说明承接对象，结尾说明已有输出及其去向。接口须能指向真实材料，例如“上一问的［输出］作为本问［输入］，单位为［单位］，具体使用见［位置］”；未被复用的结果无需附加接口。

引用紧邻其支持的定义、数据来源、方法或判断，文献表与正文引用对应。AI 声明依据实际使用记录与用户提供的格式书写。附录仅编排和索引用户提供的推导、代码、数据、图表及说明，保持附件名与正文引用一致；可报告材料缺失和索引冲突，不补写程序、不宣称完成运行复现。

## 常见失效与编辑检查

| 失效信号 | 编辑处理 |
|---|---|
| 全局“模型—算法—结果”分章导致各问答案难找 | 按逐问闭环重组已有段落，确需共享的内容保留引用接口 |
| 各问误差、敏感性等结果集中到统一检验章，或只用段落承载 | 归回各问 `\section`，按分析类型分别设置 `\subsection`；共享方法引用保留，本问结果与解释就近呈现 |
| 问题分析只有方法名 | 查找用户提供的困难与选用理由；缺失则提问 |
| 假设堆砌、符号表收录全部局部符号 | 依据正文调用精简假设；跨章符号集中、局部符号就近 |
| 公式连续堆叠或解释跨越缺失推导 | 补充已有关系的文字说明，缺失技术环节标为待确认 |
| 只有图表、没有答案与题目含义 | 用现有结果增加直接答案和证据解释，不新增计算 |
| 检验只说“效果良好”，评价只说“合理有效” | 索引已有指标、阈值与证据；缺失时保留明确边界 |
| 结论首次出现答案，或推广超过材料支持范围 | 将答案放回对应问题，限定结论和推广范围 |
| 附录索引被写成程序开发／复现任务 | 仅维护用户材料的名称、位置、用途和对应题问 |

交付前逐项检查：题问与输出是否覆盖；首次答案是否就近；跨问接口是否真实；公式、符号、单位和数值是否前后一致；分析型图表是否具备当前主张所需的引导与解释、描述型表是否说明用途与读取方式；检验、评价、摘要是否共享同一证据与边界；标题和附件引用是否对应；未确认项是否明确标出。此处检查属于文稿审阅，不代替用户的技术验证。
