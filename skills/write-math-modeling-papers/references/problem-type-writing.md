# 按题型组织用户技术材料

## 用途与边界

本文件指导“如何把用户已给技术内容写清”，不提供选模指南。按用户已经完成的技术内容识别表达需要，同一题可使用多个类型的叙事要点；题型标签不授权选择、构建或修改模型。

各类型均只提取、编排、引用和解释用户已给的模型、公式、推导、算法、数据处理说明、结果、图表及检验。禁止补推导、算数、调参、生成或运行代码、建议新方法、设计或执行实验。材料缺失时只问缺失事实及其来源，不提供候选方法或假想结果。一致性审阅发现符号、量纲、公式或结果疑点时报告位置，交由用户确认。

共同章节结构见 [chapter-workflow.md](chapter-workflow.md)。以下叙事顺序提供按内容选择的信息功能，允许省略不适用项、跨相邻段落合并或承接，每项无需独立设标题；描述型表按用途交代字段与读取方式，不套用分析型图表的趋势／原因解释要求。仅当前任务或主张确需而用户材料缺失的内容进入缺口交接，具体标题见 [heading-naming.md](heading-naming.md)。

## 优化型（optimization）

### 应提取的事实

题目要求的决策对象与范围；用户给定的决策变量、取值域、目标及其方向、约束和参数来源；已有多目标权衡依据；已采用的算法及选择理由、输入和核心步骤；用户报告的可行性、目标值、完整方案、求解状态及已知界限。

### 推荐叙事顺序

决策任务与输入条件 → 变量与目标 → 约束和参数来源 → 用户已有求解过程 → 方案与目标值 → 可行性证据和适用边界。约束按用户材料中的实际含义分组，解释它们对应的题目限制。

### 公式、图表与结果呈现

目标函数、约束组及变量域相互引用，公式旁说明方向、单位和参数出处。方案表呈现用户提供的决策值、目标值与必要条件；已有方案图或趋势图解释对象关系与可见变化。首次完整答案就近给出“在什么条件下，采用哪一套方案，得到何种目标值”。“最优”须有用户提供的最优性证据或明确的求解状态；仅有可行方案时按可行方案叙述。

### 检验与边界写法

写清用户已提供的可行性核验对象、指标／容差、结果和判定，已有敏感性或比较材料说明参数范围与方案变化。全局最优、局部最优、当前最好结果和可行结果按用户证据区分；运行时间及稳定性只引用已有记录。缺失约束核验或状态记录时不代算、不重新求解。

### 常见空泛与断链

只列算法名；目标与题目要求不对应；约束没有现实解释；参数与阈值缺少来源；目标值与方案脱节；可行性未说明却称“最优”；评价的高效性没有比较记录。

### 材料缺失时的精确问题

- “决策变量各分量的含义、单位和允许取值在哪份材料中？”
- “约束中的参数［名称］取自题目、数据还是你已完成的估计？请提供对应位置。”
- “方案［编号］的目标值、求解状态和可行性核验记录分别在哪里？”
- “正文使用‘最优’的依据是哪条已有证明、界限或求解记录？”

## 数据预测型（prediction）

### 应提取的事实

预测对象、预测时点与跨度、样本和时间覆盖；用户已完成的预处理步骤、理由及影响；特征定义、可用时点和已有关系说明；用户采用的模型及输入输出；训练、验证、测试划分；指标定义及实际值；误差、区间和用户说明的外推边界。

### 推荐叙事顺序

预测任务与数据范围 → 预处理理由与已知影响 → 特征／关系及模型表达 → 训练验证划分与已完成过程 → 预测值和指标 → 误差解释及外推范围。

### 公式、图表与结果呈现

公式交代预测量、特征、时间索引与参数含义，引用用户现有的指标定义。精确预测值用用户提供的结果表，实际与预测曲线、残差图或区间图只引用已有图表并说明训练／测试区域。图后指出用户结果支持的趋势和误差特征，不自行求差、汇总指标或生成区间。

### 检验与边界写法

逐项交代已有验证使用哪段数据、什么指标及其值，区分训练表现与验证／测试表现。外推范围限定在用户说明的时间、对象、特征范围及数据条件内；预处理影响、信息泄漏或分布变化只据用户材料表述，发现时点或划分矛盾时提出具体疑点。

### 常见空泛与断链

只写“清洗后建模”；预处理理由与影响缺失；特征在预测时不可获得却未说明；划分规则不明；训练指标被当成外推能力；只画拟合图而没有题目要求的预测输出；把相关关系写成因果原因。

### 材料缺失时的精确问题

- “［预处理步骤］的既有理由与处理后影响记录位于哪里？”
- “训练、验证和测试样本分别覆盖哪些对象或日期，划分规则是什么？”
- “特征［名称］在所述预测时点是否已可获得？请提供你已采用的定义。”
- “指标［名称］对应哪个数据子集、哪一版预测结果？已有误差与外推边界如何说明？”

## 综合评价型（evaluation）

### 应提取的事实

评价对象、目的与比较范围；用户给定的指标含义、方向、单位、数据来源、处理方式；权重及其依据；已有综合表达式、得分与排序；差异解释、敏感性和适用条件。

### 推荐叙事顺序

评价目的与对象 → 指标含义和方向 → 用户已有指标处理与权重依据 → 综合表达 → 得分／排序与任务回答 → 敏感性证据及评价边界。

### 公式、图表与结果呈现

指标表把名称、含义、方向、单位和来源对应起来，权重表与综合公式使用相同记号。结果引用用户给定的得分、排序及已有分差；已有分布图或雷达图说明各对象的优势维度和整体表现。指标方向转换、归一化值、权重和得分只转述用户提供的结果，不新增计算。

### 检验与边界写法

说明已有敏感性针对哪个权重／指标、范围如何、排序或得分如何变化以及用户的判定。评价结论限定在用户给定的指标体系、对象集合、时期和价值取向内；缺失敏感性材料时标明尚无对应支持，不宣称排序稳健。

### 常见空泛与断链

指标名缺少现实含义；正负方向不明；权重只报数值；不同数据口径直接比较；综合分数与题目决策脱节；没有敏感性证据却把排名写成普遍优劣。

### 材料缺失时的精确问题

- “指标［名称］的方向、单位、来源及你采用的处理方式是什么？”
- “权重［数值或表位置］的依据在哪份已有材料中？”
- “最终得分和排名以哪个文件／版本为准？”
- “你已有的敏感性结果支持哪些权重范围或对象范围内的排序结论？”

## 统计分析型（statistical）

### 应提取的事实

总体与样本、抽样或观测范围、样本量和单位；用户已采用的分布或独立性等假设；待检验命题、统计量、估计量、阈值及来源；已有检验结果、效应量和区间；两类错误的相关说明，或该分析适用的诊断材料。

### 推荐叙事顺序

统计问题与样本范围 → 用户采用的假设和命题 → 统计量／估计关系及阈值 → 已有结果与判定 → 现实含义 → 两类错误或适用诊断及推断边界。用户材料只涉及估计或描述统计时，按实际目的组织，不强行加入假设检验。

### 公式、图表与结果呈现

公式说明总体参数、样本统计量及样本索引，清楚区分假设、检验统计量、显著性阈值和已有 p 值。表格就近列出用户提供的样本量、效应量、区间和判定；已有分布图、残差图或分组图说明差异形态。未提供的统计量、p 值、区间及阈值不自行计算或设定。

### 检验与边界写法

引用用户已有的假设适用诊断，写清支持范围；涉及两类错误时解释用户所述第一类／第二类错误与当前判定的关系，不生成错误概率。区分统计显著性、效应大小与题目意义，拒绝／未拒绝的对象表述与用户原假设一致。样本推断到总体的条件按已有材料交代，关联结果不扩写为因果证明。

### 常见空泛与断链

未定义原假设就给出 p 值；样本量与总体范围混淆；把“未拒绝”写成证实；阈值无来源；只报告显著性而不解释实际效应；诊断缺失却声称所有假设成立。

### 材料缺失时的精确问题

- “这项分析的总体、样本范围及样本量分别是什么，记录位于哪里？”
- “原假设／备择假设及采用的阈值如何表述，阈值依据是什么？”
- “统计量、区间或 p 值对应哪一份既有结果？”
- “你已提供哪些两类错误说明或适用诊断，能支持到什么范围？”

## 机理与仿真型（mechanism/simulation）

### 应提取的事实

用户描述的机制关系、系统对象、状态变量和状态转移；已有方程、离散关系及推导；边界条件、初始条件、参数及来源；用户已完成的求解／仿真步骤和设置；状态轨迹、关键事件、误差或敏感性结果。

### 推荐叙事顺序

现实机制与任务 → 状态和关系表达 → 边界初值及参数来源 → 用户已有求解／仿真过程 → 轨迹与题目输出 → 误差、敏感性及适用边界。

### 公式、图表与结果呈现

按已有推导顺序解释机制方程、状态转移与变量单位，初值和边界紧邻相关公式。时间／空间轨迹图注明范围、初始场景和关键状态；关键时刻、峰值及状态量引用用户已有精确结果表。步长、采样间隔、输出间隔和展示精度如有提供应分别说明，不自行设置或改变。

### 检验与边界写法

写明已有误差比较的对象、参照、指标和判定，敏感性说明哪些参数或条件变化、用户结果如何响应。理想化机制、边界条件、参数有效范围和离散处理影响依据用户材料说明。推导断点或量纲疑点只定位报告，不补推导、不回代或重新仿真。

### 常见空泛与断链

直接给方程而缺少机制解释；初值与边界缺失；状态转换条件不明；参数来源未交代；仿真图与题目答案脱节；把某个场景的轨迹解释为一般规律。

### 材料缺失时的精确问题

- “状态［名称］之间的机制关系或转换条件在已有材料中如何定义？”
- “方程［编号］使用的初值、边界及参数来源分别是什么？”
- “图［编号］对应哪个已有仿真场景，精确关键结果记录在哪里？”
- “误差或敏感性结果覆盖哪些条件，其参照与判定依据是什么？”

## 网络与图型（network/graph）

### 应提取的事实

节点和边的现实含义、方向、权重及来源；用户给定的网络范围、指标定义、路径／连接／流量等任务；已有图表示、约束、算法过程及输出；用户报告的路径、方案或网络指标及已有验证。

### 推荐叙事顺序

任务与网络范围 → 节点边及权重语义 → 用户已有指标和图上表达 → 已完成过程 → 路径／方案与可视化解读 → 检验和网络边界。

### 公式、图表与结果呈现

图集合、邻接关系、边权和指标符号与正文一致，说明有向／无向等用户已确认属性。已有网络图解读图例、节点类型、边方向和重点路径；精确路径顺序、边权或方案值引用用户表格。图上位置只在用户说明其现实意义时作地理或距离解释，图的视觉布局不作为未提供指标的证据。

### 检验与边界写法

引用用户已有的路径可达性、限制条件或方案核验记录，写明检查对象、指标、结果与结论。网络缺失、权重时间性、方向假设或观测范围的影响按用户材料限定，不自行补边、计算指标或搜索路径。

### 常见空泛与断链

节点边没有现实定义；边宽和颜色缺少图例；路径名称与节点编号不一致；图示看似中心却被写成中心性结论；给出方案而未说明适用网络范围。

### 材料缺失时的精确问题

- “节点、边、方向和权重分别对应什么现实对象，其定义与来源在哪里？”
- “指标［名称］的用户定义及现有数值位于哪份材料？”
- “最终路径／方案的精确节点顺序、条件及核验结果是什么？”
- “图中位置、颜色和边宽分别表达什么，是否有现成图例说明？”

## 混合型（hybrid）

### 应提取的事实

用户方案中各模块的任务、模型、输入输出与材料位置；模块执行或逻辑顺序；传递变量的含义、单位、对象和时间范围；已有转换规则、接口条件与版本；模块结果、综合结果以及已有误差传递或整体检验材料。

### 推荐叙事顺序

总任务与模块职责 → 各模块已有输入和处理 → 输出到下一模块的接口 → 分模块结果 → 综合答案 → 模块边界与已有整体检验。独立模块平行介绍，有真实依赖的模块按依赖顺序展开。

### 公式、图表与结果呈现

公式保留各模块已定义的变量，明确同一符号跨模块是否保持同一语义。可用文字或接口表索引“来源模块—传递量—单位／范围—目标模块—用途”，每格限已有事实；引用用户已有框架图解释信息流。综合结果就近指出使用了哪些已给模块输出，避免只拼接方法名称。

### 检验与边界写法

模块检验支持对应模块，整体检验支持用户记录的综合结论；两者的对象与边界分别叙述。接口误差、范围变化或版本冲突按已有说明呈现，未有传播分析时不能声称总体误差已受控。发现接口单位或数据范围不一致时精确报告，不自行换算、修补接口或补充集成实验。

### 常见空泛与断链

只写“融合多种方法”；模块输出如何进入下一模块不明；对象／时间范围不一致；模块有效性直接等同于整体有效性；综合答案无法追溯到具体输入版本。

### 材料缺失时的精确问题

- “模块［甲］的哪个已有输出进入模块［乙］，作为何种输入、约束或参数？”
- “传递量的含义、单位、对象范围和版本分别是什么？”
- “接口转换规则已在哪份材料中定义？”
- “哪些记录属于模块检验，哪些属于整体检验，分别支持哪项结论？”

## 缺口交接与编辑收束

缺口记录采用“题问／模块—材料位置—缺少或矛盾的具体事实—受影响的句段／结论—向用户提出的问题”。已有内容继续编排，依赖缺失事实的句段标为待确认；不以常见做法填充事实，不生成数值占位结果，不建议用户采用其他技术方法。

最终检查各问的对象、方法、直接答案、图表证据、检验与边界是否连通；所有技术断点归还用户处理。此文件的题型叙事用于提高现有材料的可读性，不能作为已完成技术验证的证据。
