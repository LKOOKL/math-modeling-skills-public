# 数学建模论文写作与提交检查表

## 使用范围与记录方式

全文审查覆盖本清单；局部任务仅检查所改内容及直接受影响项，列明未覆盖的全文事项。每项记录 `通过／待修改／待提供／待核验／不适用`、位置与依据。“通过”仅指本次实际文稿检查，技术正确性和可运行性依用户材料说明。

先读取当届全国官方规则、题目要求及提交说明，记录标题、版本、链接、核验日期与适用范围。赛区材料只在全国允许的范围内补充，经验材料用于编辑建议；出现冲突时标明条款并向用户确认，赛区材料不覆盖全国规定。

## 一、年度提交硬门

设计基线来自[2026 全国论文格式规范](https://www.mcm.edu.cn/html_cn/node/4cd596519c9eb9fbd866398f6df0caa3.html)与[2026 全国 AI 工具使用规定](https://www.mcm.edu.cn/html_cn/node/fef94648f2836ab6cc81586f4c38512b.html)。下表用于核查入口，不作为未来年份的固定规则。

| 检查项 | 2026 设计基线 | 使用要求 |
|---|---|---|
| 电子稿首页 | 摘要专用页；不含承诺书、编号专用页 | 使用时以当届官方文本为准 |
| 摘要与页码 | 摘要原则上一页，含标题与关键词；从摘要连续编页码 | 使用时以当届官方文本为准 |
| 正文目录与篇幅 | 正文不设目录，不超过 30 页；附录另计 | 使用时以当届官方文本为准 |
| 论文文件 | 单一 PDF 或 Word，建议 PDF；不压缩，不超过 20 MB | 使用时以当届官方文本为准；本 Skill 以 LaTeX 生成 PDF |
| AI 披露 | 声明位于参考文献前；已使用者提交 AI工具使用详情.pdf | 使用时以当届官方文本为准 |
| 附录与支撑包 | 附录列清单及源码等；支撑包单独提交，RAR／ZIP，不超过 20 MB | 使用时以当届官方文本为准 |
| 匿名与一致性 | 论文相关页面、附录与支撑文件匿名；纸质／电子内容格式一致 | 使用时以当届官方文本为准 |
| 其他提交参数 | 纸张、页边距、文件命名、截止时间、提交平台及补充要求 | 使用时以当届官方文本为准，逐项记录适用值 |

未获得适用规则的项目标记“待核验”，不据历年模板宣称合规。论文正文不设目录与内部章节规划、PDF 书签属于不同事项，应分别检查。

## 二、文稿证据与作答硬门

- [ ] 一级骨架对照 [用户国赛模板契约](user-template-contract.md) 核验，问题重述至评价推广、参考文献及附录的顺序保持；实际题数、局部小修与必要例外有记录，模板示例事实未混入成稿。
- [ ] 每问每个最终作答模型在本问建立／求解部分至少由伪代码或流程图之一覆盖；有编号、标签、正文引导解释、输入输出和实际步骤，来源可定位。仅总图、占位图、示例K-Means、代码截图或文件清单不能算完成；理论模型可用已有论证流程。
- [ ] 每问“题目要求—用户方法—结果—证据—直接答案”可定位，共享内容和跨问输入有明确对应。
- [ ] 按实际 LaTeX 层级逐问检查：每问为 `\section`，结果分析、误差分析、敏感性分析及其他适用检验分别为其下的 `\subsection`；仅有文件名或标题文字不算归属正确。显式格式例外有来源记录。
- [ ] 各分析小节包含本问的关键结果、解释与边界，或具体缺口／不适用理由；共享方法及大表可引用，统一检验总章、单句交叉引用或附录索引未替代逐问分析。缺失项没有被写成通过，写作阶段没有补算。
- [ ] 来源、采用版本、用户确认状态与文稿检查状态已记录；缺失为具体占位符，冲突主张暂停写入定稿。见 [writing-input-and-evidence.md](writing-input-and-evidence.md)。
- [ ] 篇幅与讨论按本问任务、证据和适用规则验收；字数和讨论维度只作编辑建议，未以填满配额为由补造检验。确定性计算及无原始样本的题目允许简短事实说明，逐问分析层级仍保留。
- [ ] 按 [tracking-format.md](tracking-format.md) 核对追踪标记：TeX 使用独立注释行或外部映射，PDF 正文未泄漏内部编号，注释后的必要正文仍可见。
- [ ] 摘要与正文的模型名、数值、单位、条件、范围及结论一致；摘要重要主张能返回正文证据。
- [ ] 假设与题目事实分开，依据和影响忠实呈现；符号在使用时有定义，单位与索引清楚，公式有条件、来源和含义说明。
- [ ] 求解叙述忠实于用户材料，参数、步骤、停止条件等已提供信息准确；缺少的技术说明未被自行补造。
- [ ] 结果和图表回答题问，检验、误差、敏感性或比较仅叙述用户已有记录；执行状态、支持结论及边界清楚。
- [ ] 评价的优点、局限和已有改进讨论有前文依据；最优性、因果性、稳定性等主张未超出证据。
- [ ] 参考文献与正文引用双向对应，引用来源可定位，未把 AI 使用详情混作学术证据。
- [ ] AI 声明与实际参与一致，工具及环节无遗漏，人工修改和核验记录真实；见 [ai-writing-and-disclosure.md](ai-writing-and-disclosure.md)。
- [ ] 论文附录、支撑包、AI 详情与正文双向映射，实际文件和清单一致，缺件精确记录；见 [appendix-and-supporting-materials.md](appendix-and-supporting-materials.md)。
- [ ] 摘要、正文、附录、图像、文件属性及支撑材料的身份信息均在实际可读范围内完成匿名检查。

## 三、排版与可读性硬门

- [ ] LaTeX 是唯一正文源；编译仅处理排版，涉及求解、数据处理或代码执行的依赖已停止并记录。
- [ ] 实际编译状态、入口、日志和未解决问题明确；交叉引用、资源、字体与中文显示正常。
- [ ] PDF 已按任务范围审阅：公式图表无裁切重叠，标签与书签正确，页码及当届页数／大小合规。
- [ ] 图表前说明目的，后解释读数或用途；页面尽量图文配合，必要纯文本页可保留，禁止整页只有缺乏正文解读的图表。
- [ ] 源码展示保持文本、缩进与字符可读，未用截图代替；附录只声明实际静态检查及用户提供的运行依据。

排版操作与逐页项目见 [latex-production.md](latex-production.md)。缺少最终 PDF 或仅检查局部页面时，明确列出未核验范围。

## 四、编辑建议

以下用于提高表达与导航质量，具体采用随内容与篇幅决定：

- 标题范围与语义清楚，同级粒度平行，少用重复空泛标题；见 [heading-naming.md](heading-naming.md)。
- 章节开头承接任务，结尾给出答案和接口；结构参考 [chapter-workflow.md](chapter-workflow.md)。
- 精确值用表，趋势和差异用已有图件；避免重复呈现。描述型表按用途解释，不要求趋势段。
- 压缩套话，统一术语与有效数字展示；处理孤行、孤立标题和留白时保留可读字号及充分解释。

## 五、退回用户的技术事项

发现以下问题只记录材料缺口与影响，不执行技术修复：

- 模型、约束、推导或证明缺失，以及需要重新选择方案的疑点。
- 数值冲突、约束满足情况不明、误差或敏感性证据缺失，需要用户复算或验证的事项。
- 源码缺失、命令或环境说明不全、可运行性依据不足、运行记录与结果版本不匹配。
- 需要新实验、调参、数据处理或图表再计算才能回答的主张。

未关闭项保留 `[待提供：具体材料]` 或收窄相应文字主张；不得为完成审稿而启动程序、补算结果或声称完成验证。

## 六、审稿问题与交付格式

| 严重级别 | 位置 | 问题 | 证据／规则 | 建议写作修订 | 需用户动作 |
|---|---|---|---|---|---|
| P0 规则／真实性阻断 | [文件、页或章节] | [具体问题] | [当届条款或事实冲突] | [可直接修订范围] | [确认／补充事项] |
| P1 作答／证据缺口 | [位置] | [具体问题] | [材料及版本] | [占位、标注或收窄主张] | [补充技术材料] |
| P2 结构／一致性 | [位置] | [具体问题] | [前后对应内容] | [术语、引用或组织调整] | [如需确认] |
| P3 表达／版式 | [位置] | [具体问题] | [文本或页面观察] | [局部文字或排版调整] | [如需确认] |

材料充分的纯表达问题，在“建议写作修订”中附可直接替换的 LaTeX 文字，保留技术含义、数值、引用及用户采用版本。技术缺口或需要重新求解、技术判断的事项只列入“需用户动作”，说明缺少材料与影响位置，不生成替换技术内容。

“只审查”请求仅报告问题和替换建议，不自动修改正文；已授权改稿时，可直接修改措辞、章节组织、标签、引用和排版。事实冲突、模型与数值变更、缺失推导、源码和验证事项退回用户。交付一次列出修改范围、实际检查与结果、未关闭问题；含关键占位或冲突的文稿标为未完成稿。
