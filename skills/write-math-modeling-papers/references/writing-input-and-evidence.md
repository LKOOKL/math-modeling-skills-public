# 写作材料准入与证据契约

在首次整理材料、接收新版本或发现冲突时使用本文件；规则层级见 [evidence-and-scoring.md](evidence-and-scoring.md)。所有模型、公式、参数、结果和验证结论均来自用户材料。用户提供不自动等于技术正确；本 Skill 仅做写作准入和编辑一致性审查，不建模、不推导、不算数、不运行代码或实验，也不签署技术正确性结论。

## 每问材料：13 个字段

逐问登记；最低可写条件按字段判断。缺少某项时可写其他有依据的部分，完整结果段和摘要中的对应主张须等待所需材料齐备。用户确认某字段不适用时记录理由，不强制创造内容。

| 字段 | 内容与最低可写条件 |
|---|---|
| `question_id` | 与题面一致的题号及子任务号，能唯一对应题问。 |
| `task` | 用户提供的目标、输入、输出与题面位置；能准确复述本问要求。 |
| `method` | 已采用的模型/方法名称、用途及用户给出的选择依据；仅有候选方法时保留候选身份。 |
| `assumptions_symbols` | 用户提供的假设、符号含义、单位、索引和适用范围；涉及的符号与假设须可定位，不代定假设。 |
| `formulas` | 已提供的数学表达、公式编号或来源位置及条件；需要解释的推导须有用户推导记录，不自行补证或修正。 |
| `procedure` | 每问每个最终模型已采用流程的输入、步骤、参数与停止条件（适用时），以及拟展示的伪代码／流程图标签与来源；区分计划与实际执行。可据完整已有流程转排，缺步骤时登记缺口，缺执行记录时只写方法描述。 |
| `results` | 直接答案、数值/方案、单位、精度、条件和版本；定量结果须有可定位直接输出，不由 Skill 计算或从图像估读。 |
| `figures_tables` | 已有图表/数据表、文件名、标题、单位及其支撑主张；转排保留已有数值和含义。流程展示可根据完整已有说明编排并标注来源；缺结果图或缺流程材料时先留具体缺口。 |
| `validation` | 用户提供的检验类型、对象、条件、实际输出与解释；只有计划时仅登记待完成，不写“已验证”。 |
| `scope_limits` | 已说明的适用条件、局限和主张强度；最优性、因果性、稳定性、推广性需用户给出对应依据与边界。 |
| `dependencies` | 所依赖题问、参数、模型和结果的版本及位置；无依赖须明确记录，依赖变化触发受影响内容重新准入。 |
| `sources` | 每项事实的用户材料文件名/版本及页码、表格单元、输出字段等定位；外部引用须有原始来源信息。 |
| `status` | 下述四状态之一，按字段或主张登记，并附依据、版本和日期；整问概括状态不得掩盖局部缺口。 |

复制此纵表，每问填写一张；各字段分别记录状态、依据、版本和更新时间，`status` 行汇总本问状态并列出局部缺口：

## 全文材料

| 材料 | 最低登记要求 | 缺失影响 |
|---|---|---|
| 当届规则 | 官方原文/链接、年份、适用赛区、发布日期或版本、核验日期 | 暂缓相关合规结论，具体数值不沿用旧届 |
| 题目与附件 | 完整题面、数据说明、附件及版本 | 暂缓受影响的题问范围和交付要求 |
| LaTeX 模板 | 按 [用户模板契约](user-template-contract.md) 登记采用的TeX/JSON版本、快照、一级骨架、过程展示要求及小修记录 | 可先写有依据内容；当届合规与编译状态分别核验，模板元数据和样例不作为论文事实 |
| 参考文献 | 真实条目、原始来源、正文用途与支持位置 | 对应外部事实留引用缺口，禁止编造条目 |
| 附件清单 | 实际文件名、题问、用途、版本和正文引用位置 | 缺失附件登记缺口，不宣称附件齐备或可复现 |
| 真实 AI 使用记录 | 实际工具/版本、用途、采纳内容、人工修改与核验记录，按当届规定所需范围整理 | 不代造交互和核验历史；缺项交用户补充 |

## 四状态与允许写法

状态描述材料的写作资格，不代表 Skill 证明了数学或计算正确性。“附有证据”表示已找到相符、可定位的支撑材料，技术效力仍受其类型和范围限制。

| 状态 | 进入条件 | 允许写法与边界 |
|---|---|---|
| 用户确认 | 用户明确确认内容、版本或选择，尚缺直接证据 | 可整理方法、假设与限定描述；无直接输出的数值及“最优/显著/稳健”等强主张暂缓进入正式结论 |
| 附有证据 | 已收到与主张、版本、条件相符的可定位直接材料，且未发现编辑一致性冲突 | 在证据覆盖范围内写事实并保留引用；一次运行只支持该次输出，验证记录只支持其检验范围 |
| 待提供 | 内容缺失、位置不可定位、证据不足或新版本的支撑尚未提供 | 使用 `[待提供：具体内容]`；不将草稿占位写成事实 |
| 存在冲突 | 同一事实的来源、版本、数值或条件相互不一致 | 关闭相关定量主张及其摘要、评价和跨问引用，登记差异，等待用户确认 |

升级须记录新依据：补齐材料可由“待提供”转为“用户确认”或“附有证据”；用户确认本身仅支持前一状态。冲突须先有用户明确裁决，再按选定版本证据恢复状态。材料撤回、来源失效或模型/参数/结果版本变化时，下游主张降为“待提供”；发现不一致时改为“存在冲突”。禁止因文本润色、重复出现或 AI 赞同升级状态。

## 缺口与冲突处理

缺口统一写为 `[待提供：具体内容]`，指出题问、所需材料及用途；集中维护下表，同时继续写不受影响的段落。禁止虚构参数、推导、结果、检验、图表、参考文献、AI 使用记录或执行历史。

| gap_id | question_id | missing_content | affected_location | required_material | status |
|---|---|---|---|---|---|
| G01 | Q1 | [待提供：具体内容] | 摘要/正文位置 | 文件、输出字段或用户确认事项 | 待提供 |

冲突差异表每个候选版本一行；保留原材料，禁止平均冲突值、挑选更优结果、静默改公式或自行裁决技术正确性。将受影响主张在追踪矩阵中标为“存在冲突”，关闭相关定量表述并等待用户确认；独立段落继续写作。

| item | location | version | evidence | affected_claim | decision_needed |
|---|---|---|---|---|---|
| 冲突项 | 文件与页码/单元/字段 | 候选版本 | 原文、原值及条件 | Q1-C01 及其引用位置 | 请用户确认采用版本并提供依据 |

## 一致性与写作变更记录

逐问补充过程展示映射：`题号 → 最终模型 → 伪代码或流程图标签 → 本问正文位置 → 已有流程/源码的版本与位置 → 完成或具体缺口`。覆盖要求适用于每问模型；本映射是文档证据，不构成已运行该算法的证明。

逐项对照摘要、正文、公式、图、表和附件中的数字、单位、精度、符号、模型名、题问范围及文件名；只比较用户已有表达，不补算换算值、误差或统计量。单位或精度差异需要技术判断时回填冲突/缺口表；可疑等式、约束、量纲或推导仅报告位置与疑点并退回用户确认，不修数学。

写作变更记录模板内的局部重排、压缩、术语统一、展示型伪代码／流程图转排及纯排版修复；保留公式条件、数值、限定语、技术含义与证据指向。术语统一先确认同义关系；不确定时报告差异。用户后续提供的技术修订登记为新的输入版本，与 Skill 的编辑修改分开记录。

| change_id | manuscript_location | edit_type | before_after_summary | source_anchor | technical_content_preserved |
|---|---|---|---|---|---|
| W01 | 章节/段落 | 编辑重排/压缩/术语统一 | 简述编辑变化 | 原材料版本与位置 | 已逐项对照/待用户确认 |
