# 数学建模论文写作

将用户提供的题目、模型、公式、算法说明、结果、图表、检验证据、引用、附件与规则组织为中文数学建模竞赛 LaTeX 论文。保持技术含义、来源和版本可追溯。

## 核心边界与输入准入

- 本 Skill 承担零求解职责：不选择或建立模型，不补推缺失推导，不生成、修改或执行求解代码，不进行数值计算、参数调优、实验或验证执行。
- 可以检查符号、量纲、公式衔接、引用对应和跨载体数值一致性；检查用于发现与报告疑点。数学修复、补充证明和重新求解均单列退回用户。
- 写作可重组语句、章节、公式排版及图表说明，忠实叙述用户已提供的方案依据和求解过程；不得借“润色”改变模型、约束、算法、参数或结果。
- 可依据已有模型、算法说明或已提供代码，转写展示型伪代码和流程图及其 LaTeX/TikZ 排版源码；这属于过程表达，不设计新算法、不补推步骤、不修改或运行求解代码。每问模型的展示要求见 [用户模板契约](references/user-template-contract.md#每问模型的过程展示)。
- 输入包括题目和用户求解包；求解包按题问收录已有模型、推导、算法说明、结果、图表、验证记录、引用及支撑材料。记录实际读取的来源、位置和版本。
- 每项材料标注“用户确认 / 附有证据 / 待提供 / 存在冲突”；用户提供或确认均不自动代表技术正确，“附有证据”也不等于本 Skill 已复验。
- 缺失内容统一使用 `[待提供：具体内容]`；冲突关闭相关定量主张的写入资格，等待用户明确依据和采用版本。继续完成独立且证据充足的写作部分。
- 首次盘点、材料更新或发现冲突时，读取 [writing-input-and-evidence.md](references/writing-input-and-evidence.md)。

## 输入路由：已有材料与内部求解交接

- 用户要求“已有结果，重写论文／排版”时，优先进入本 Skill。登记已有解答、表格、算法说明和检验证据的来源、版本及状态；无需先创建本套求解流程的 PoC、决策日志或 `frozen_numbers.json`。等价材料按实际内容准入，缺失内容留在相应题问，继续证据充分的部分。
- 本套技能已完成建模求解后再交接时，沿用内部求解包、冻结结果及决策记录，保留真实决策归属；主稿中的引用状态与检查状态分别报告。
- 既有自主授权、人工保留点及代理决策记录按 [包内授权契约](../workflow-orchestrator/references/decision-authority.md) 处理。本 Skill 的零求解职责持续适用：新技术判断交回已获授权的生产环节，不能借写作入口补算或重做历史决策。

## 三种工作模式与输出契约

| 模式 | 适用任务 | 交付内容 |
|---|---|---|
| 规划与材料审计 | 整理写作材料、规划结构、检查缺口 | 材料及状态清单；缺口与冲突表；题问—主张—证据—正文位置矩阵；内部章节提纲、标题路径及各节所需材料；逐章写作卡（目标、输入、信息顺序、交付内容）；公式、图、表、结果、引用、附件的载体布置方案 |
| 撰写与改写 | 全文、章节或已有稿件的表达与排版 | 可直接进入 LaTeX 的正文或完整项目；来源对应说明；具体占位符；保留的技术疑点；实际编译状态 |
| 终稿审查 | 检查成稿的作答、证据和提交规范 | 按优先级列出的“位置—问题—依据—影响—写作修改或退回事项”；材料充分的纯表达问题附可直接替换的 LaTeX 文字；需要重新求解或技术判断的缺口只列退回事项；逐问覆盖与摘要一致性结果；规则及编译检查记录；未关闭问题 |

按用户请求选择模式，可组合执行；审查请求仅报告问题与建议，正文修改遵循用户授权。审计结论仅覆盖实际读取材料与实际执行的检查。

内部提纲不作为正文目录输出。

局部写作与专项审查只执行相关步骤、读取相关引用并检查受影响内容，按当前任务范围裁剪交付内容；全部求解边界与证据要求持续适用。

## 主流程与按需阅读

1. **读取当届规则与题目。** 确认赛事、年份、题号和提交范围，提取各问任务及接口；官方规则优先。涉及评分或规则依据时读取 [evidence-and-scoring.md](references/evidence-and-scoring.md)，规则缺失时明确待提供或核查项。
2. **盘点用户材料。** 按题问登记来源、版本、状态和可写范围；结果与检验记录依用户材料陈述，不赋予本 Skill 未取得的验证结论。
3. **列出缺口与冲突。** 指明所缺内容及影响的章节或主张；将需建模、推导、计算、改代码或重做验证的问题归入“需用户补充或重新求解”清单。
4. **建立追踪矩阵。** 为每问列出“题问—主张—证据—正文位置”，让直接答案、图表、公式和来源均有落点。涉及决定或证据标记时读取 [tracking-format.md](references/tracking-format.md)：LaTeX 使用独立行 `%` 注释，Markdown 可使用 HTML 注释，检查最终 PDF 不泄漏内部编号。
5. **确定结构与标题。** 先读 [user-template-contract.md](references/user-template-contract.md)，按用户国赛模板固定大框架，再读 [chapter-workflow.md](references/chapter-workflow.md) 和 [heading-naming.md](references/heading-naming.md)，将写作经验用于章内表达和获准小修。需要特定题型的叙述方式时读取 [problem-type-writing.md](references/problem-type-writing.md)，仅调整写法。
6. **完成逐问主体。** 依下述逐问链组织用户已有技术材料；每问每个最终作答模型至少由伪代码或流程图之一覆盖，核对输入、步骤、输出与来源，解释公式、图表和结果，保留证据支持的适用条件和不确定性。
7. **完成收尾材料。** 依据正文证据撰写模型评价，核对引用；AI 写作及声明读取 [ai-writing-and-disclosure.md](references/ai-writing-and-disclosure.md)，附录与支撑材料索引读取 [appendix-and-supporting-materials.md](references/appendix-and-supporting-materials.md)。已有代码可原样引用与登记，不承担代码生产或复现执行。
8. **后写摘要。** 正文关键结果与采用版本明确后撰写摘要，逐问核对答案、数值、条件与贡献；摘要仍置于论文首部。
9. **LaTeX 编译与终审。** 读取 [latex-production.md](references/latex-production.md) 和 [submission-checklist.md](references/submission-checklist.md)，从唯一正文源编译并核查 PDF。只执行排版构建及文档检查；构建链若要求运行求解、实验或数据计算，暂停该环节并报告。记录实际完成项、限制与未关闭事项。

仅在对应步骤读取所需 reference；主入口中的求解边界适用于全部引用文件。

## 默认结构与逐问链

默认展示顺序严格参考用户国赛模板：题名／摘要／关键词 → 问题重述（背景、提出）→ 问题分析（逐问）→ 模型假设 → 符号说明 → 数据预处理 → 各问“模型建立与求解”（含过程展示、结果及检验小节）→ 模型的评价与推广（优点、缺点、推广）→ 按当届规则安排的 AI 声明 → 参考文献 → 附录（支撑清单、逐问源码）。实际题数、章内细分及排版小修按 [用户模板契约](references/user-template-contract.md) 调整；一级结构变更须有明确依据。

每问覆盖以下叙述链，篇幅与小节内部组织随问题复杂度调整；问题及分析小节层级按下述规则固定：

1. 任务与上下游接口。
2. 用户方案的已有依据。
3. 用户提供的变量、假设与模型表达。
4. 用户已完成的求解过程叙述，并以本问模型对应的伪代码或流程图呈现。
5. 直接答案及其图表证据。
6. 结果解释与任务意义。
7. 用户提供的验证结果、适用条件与边界。
8. 向下一问传递的输入、结论或条件；末问写明本问收束。

每问使用独立的 `\section`，其下分别设置 `\subsection{结果分析}`、`\subsection{误差分析}`、`\subsection{敏感性分析}`；其他适用的稳定性、稳健性、可行性或对比分析也分别设为本问的 `\subsection`，标题可加入本问对象或指标。完整编排与共享证据规则见 [chapter-workflow.md](references/chapter-workflow.md#逐问结果分析的层级与归属)。

## 硬性质量门槛

- **零求解职责。** 全文技术内容来自用户材料；需要重新求解或技术修复的问题单列退回，未经补充不得写成完成结果。
- **材料准入。** 缺失使用 `[待提供：具体内容]`，冲突关闭相关定量主张；技术确认、证据存在与本次文档检查的结论清晰区分。
- **逐问可定位。** 每问直接答案和各类结果分析、检验分别位于本问 `\section` 及对应 `\subsection`；按实际 LaTeX 层级核对归属。共享方法可引用，各问保留本问结果、解释及边界；全局检验章不能替代逐问小节。缺失或不适用项按章节规则明确记录。
- **模板与过程展示。** 一级骨架遵循用户模板，小修有对应记录；每问每个最终作答模型至少有本问正文中的伪代码或流程图，带标签、引导解释和来源。示例K-Means、空泛总流程及仅列文件名不算完成，缺材料保留具体缺口。
- **表达有解释。** 核心公式有符号、条件、来源与含义说明，图表有正文引导和读数解释，关键结果回答题目并保留适用边界；所需技术解释缺失时标为待提供。
- **全文一致。** 摘要与正文采用相同结果版本；数字、单位、符号、公式、图表、引用及附件对应一致；疑点按材料冲突处理。
- **LaTeX 单一正文源。** 正文仅由 LaTeX 项目成稿，其他草稿的有效内容迁入该项目；编译成功和检查通过仅按实际记录报告。
- **页面图文配合。** 页面尽量组合图表与解释文字，保留必要的推导文字页；最终 PDF 不得整页只有无解释的图表。
- **规则与披露真实。** 当届官方规则优先，参考文献与正文相互对应；AI 声明按真实使用范围和现有记录填写，不编造人工核验、独立验证或未使用 AI 的事实。
- **交付状态明确。** 未关闭的缺口、冲突、规则不明或编译限制随交付列出；含占位符或关键冲突的稿件标为未完成稿。
