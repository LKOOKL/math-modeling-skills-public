# 安装与使用

## 安装

1. 克隆仓库或下载并解压源码包。
2. 找到目标 Codex 的技能目录：通常为 `~/.codex/skills`；配置了 `CODEX_HOME` 时使用对应的 `skills` 目录。
3. 先查看目标位置是否已有同名技能。已有版本先备份并比较，再决定采用哪一版。
4. 将仓库 `skills/` 内的技能文件夹复制到目标技能目录，保持文件夹同级。复制的是各技能目录，不把外层仓库目录直接当成一个技能。
5. 重新开启会话，检查所需技能是否被发现。仅安装少数技能时，先查看其引用的其他技能及[依赖说明](PORTABILITY.md)。

本仓库没有自动覆盖本机技能或修改全局配置的安装器。

## 使用示例

已有求解结果，希望写论文：

> 使用 $write-math-modeling-papers，根据当前项目的题目、模型、算法、结果和检验证据完成论文写作，遵循随附国赛模板。

从题目开始推进建模：

> 使用 $workflow-orchestrator 盘点当前题目和附件，按我的授权推进建模、求解和写作，并分别记录实际完成的检查。

有明确问题的代码审查：

> 使用 $code-reviewer 审查问题二的 Python 求解代码，核对已提供的模型、输入和结果文件。

“自主完成建模、求解和写作”将范围内的决策委托给建模代理，由代理记录自己的判断和依据。“列出候选方案，让我选方法”将方法选择留给本人。两种用法共用[决策记录约定](../skills/workflow-orchestrator/references/decision-authority.md)。已有结果只需改稿时，使用上面的写作入口，缺失的检验证据留在对应题问。

## 按任务准备环境

Markdown 技能文本本身无需 Python 或 LaTeX 即可阅读。运行建模代码时，根据实际代码安装 Python 科学计算依赖或 MATLAB；编译中文论文时准备支持中文的 TeX 环境及实际需要的宏包。环境检查、脚本运行、数值核验和 PDF 审阅分别记录。

模板中的图片名、参考文献、AI 使用记录和示例算法均需依据本次题目及真实材料替换；其中示例条目不构成已完成工作。
